# FoodPlan

Сервис помогает пользователям получать готовое меню на каждый день с учётом их предпочтений: типа питания, аллергий, количества персон. Сервис автоматически формирует список покупок и рассчитывает примерную стоимость продуктов.

## О проекте

Данный проект написан на фреймворке Django и включает в себя:

- Сайт с возможностью оформления подписки, выбора типа меню и исключения аллергенов.
- Ежедневное меню из 4 блюд (завтрак, обед, ужин, десерт).
- Детальные страницы рецептов с ингредиентами, инструкцией и комментариями пользователей.
- Личный кабинет с историей подписок и статусом оплаты.
- Административная панель для управления контентом (рецепты, тарифы, промокоды, аллергены, комментарии).
- Интеграцию с платёжной системой ЮKassa.

## Настройка и запуск (локально)

1. Проект написан на [python](https://www.python.org/downloads/) версии 3.14, на версиях ниже проект может не работать или работать не так как должен, поэтому рекомендуется использовать python 3.14. Для того чтобы проверить установлен ли python, нужно ввести эту команду в терминал(cmd):
```
python --version
```
> Вывод должен быть такой, в нем будет указана версия python(если установлен): `Python 3.14.0`

2. Сохраните данный репозиторий в любое удобное место.
3. Создайте виртуальное окружение и активируйте его при помощи следующих команд:
```
cd 'путь_до_папки_с_проектом'
# для windows
python -m venv venv
venv\Scripts\activate

# для linux
python3 -m venv venv
source venv/bin/activate
```

4. Установите необходимые зависимости введя следующую команду:
```
pip install -r requirements.txt
```

5. Создайте в главной папке проекта файл для данных переменного окружения - `.env`. Заполните его по образцу из файла `env_template.txt`. Минимально необходимые настройки:
```
SECRET_KEY='Секретный_ключ_проекта'
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1
```
6. Примените миграцию к БД при помощи команды:
```
python manage.py migrate

7. Создайте суперпользователя для доступа к панели админа. Введите команду, а после укажите login, password, mail:
```
python manage.py createsuperuser
```

8. Запустите локальный сервер. На данном этапе он пригоден только для ознакомления и разработки, для продакшена он не подходит:
```
python manage.py runserver
```
После этого локальный сайт будет доступен по ссылкам: http://127.0.0.1:8000/ или http://localhost:8000/. В панель администратора можно попасть по ссылке http://127.0.0.1:8000/admin/ , при входе указываете логин и пароль, которые задавали при создании superuser на этапе 7.

## Административная панель

В БД зарегистрированы следующие модели:

- SubscriptionPlan — тарифные планы (срок подписки и коэффициент цены)
- Allergen — список аллергенов
- Recipe — рецепты блюд
- Ingredient — ингредиенты
- RecipeIngredient — связь рецептов с ингредиентами (количество, цена)
- Subscription — подписки пользователей
- PromoCode — промокоды для скидок
- DailyMenu — ежедневное меню по подписке
- Comment — комментарии пользователей к рецептам

### Управление рецептами

Для создания нового рецепта достаточно в меню выбрать раздел `Рецепты` и нажать кнопку `Добавить рецепт`. Для создания рецепта необходимо заполнить следующую информацию:

- Название рецепта
- Описание
- Инструкция по приготовлению
- Время готовки (мин)
- Калорийность
- Изображение блюда
- Тип еды (завтрак, обед, ужин, десерт)
- Тип меню (Классическое, Веганское, Кето, Низкоуглеводное)
- Аллергены (можно выбрать несколько)
- Ингредиенты

### Управление тарифами

В разделе `Тарифные планы` можно:

- Добавлять новые тарифы (например, "24 месяца")
- Указывать коэффициент цены (1.0, 1.6, 1.8, 2.0)
- Включать/отключать тарифы через флаг `is_active`

### Управление промокодами

В разделе `Промокоды` можно:

- Указывать код и процент скидки
- Ограничивать срок действия (`valid_until`)
- Ограничивать максимальное количество использований (`max_uses`)

### Управление подписками

В разделе `Подписки` можно:

- Просматривать все подписки пользователей
- Отслеживать статус оплаты (через интеграцию с ЮKassa)
- Вручную активировать, отменять или помечать истекшие подписки

### Управление комментариями

В разделе `Комментарии` можно:

- Просматривать комментарии пользователей
- Одобрять или отклонять комментарии перед публикацией (флаг `is_approved`)

## Расчёт стоимости подписки

Формула расчёта:
(стоимость выбранных приёмов пищи) x (коэффициент тарифа) x (количество месяцев)

Пример:  
Выбраны завтрак (200) + обед (300) + ужин (400) = 900 руб/мес  
Тариф "3 месяца" с коэффициентом 1.6  
Итог: 900 × 1.6 × 3 = 4 320 руб.

## Интеграция с ЮKassa

Проект поддерживает приём платежей через платёжную систему ЮKassa. Для работы необходимо:

1. Зарегистрироваться в ЮKassa и получить `shop_id` и `secret_key`
2. Указать их в файле `.env`:
```
YOOKASSA_SHOP_ID=ваш_shop_id
YOOKASSA_SECRET_KEY=ваш_secret_key
```

## Безопасность

Если Вы намерены запускать сайт в боевом режиме на сервере и пускать его в продакшн, предусмотрите вопросы безопасности.
Обязательно в переменном окружении настройте все указанные параметры, они по стандарту выставлены для возможности запустить проект локально. Без них запуск на сервере не безопасен. Откройте файл `.env` и определите следующие параметры:

```
DEBUG=False
ALLOWED_HOSTS=Ваши_домены_через_запятую
CSRF_COOKIE_SECURE=True
SESSION_COOKIE_SECURE=True
SECURE_SSL_REDIRECT=True
SECURE_HSTS_SECONDS=60
SECURE_HSTS_INCLUDE_SUBDOMAINS=True
SECURE_HSTS_PRELOAD=True
```

- DEBUG - режим отладки, при разработке нужен, но в продакшене пользователю не должна выводится отладочная информация в случае ошибки.
- ALLOWED_HOSTS - домены, на которых работает сайт(указывать через запятую).
- CSRF_COOKIE_SECURE - django проверяет, что cookie отправляются только через защищённое (HTTPS) соединение.
- SESSION_COOKIE_SECURE - сессионные куки будут передавать только по HTTPS.
- SECURE_SSL_REDIRECT - Принудительное перенаправление на HTTPS, на сайт не попасть через незащищенный запрос HTTP.
- SECURE_HSTS_SECONDS - настройка в Django, которая управляет использованием HTTP Strict Transport Security (HSTS). Она определяет длительность (в секундах), в течение которой браузер будет принудительно использовать HTTPS для доступа к сайту.
- SECURE_HSTS_INCLUDE_SUBDOMAINS - применяет HSTS ко всем поддоменам.
- SECURE_HSTS_PRELOAD - при значении True Django добавляет директиву preload в заголовок HSTS.

Перед выставлением этих настроек убедитесь, что понимаете, что каждая из них делает. Выставление некоторых настроек может привести к необратимым изменениям сайта.

Дополнительно проверьте себя нижеуказанной командой, django даст рекомендации по безопасности проекта:
```
python manage.py check --deploy
```

Также перед запуском сайта в боевом режиме, советую ознакомиться с рекомендациями по настройкам безопасности в [оф. документации django](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/).
